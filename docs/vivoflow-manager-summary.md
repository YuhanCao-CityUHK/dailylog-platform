# VivoFlow 主管任务汇总

## 交付范围

在现有项目工作台增加研发任务视图。主管通过自己的 VivoFlow OAuth 账号读取有权查看的项目、任务树和人员填报的进展；平台同时检查本地项目查看权限。项目负责人可以编辑项目关联。一个平台项目可关联多个 VivoFlow 项目，一个 VivoFlow 项目只归属一个平台项目。

首次读取真实项目目录时，先采用已经核对的初始关联，再按项目名称、产品线和平台已有别名建立明确匹配；有歧义的保留待关联。人工修改或解除后不再自动覆盖。现有项目、负责人、成员、状态、财务编码、日报和工时不作同步覆盖。

任务数量统计全部任务节点，完成数量表示任务状态，不称为项目完成率。计划截止日已过且未开始/进行中的任务为逾期。当前任务状态与所选北京时间自然日内的进展分别展示。VivoFlow 记录不写入 logs/log_items，不计入日报提交率、成果数或实际工时。

## 验证清单

- OAuth 授权码、PKCE、一次性 state 和登录会话绑定；凭证加密；刷新串行；断开清除个人缓存。
- 项目列表、任务树和进展游标完整读取；循环游标、截断、服务不可用明确提示。
- 本地项目权限与个人远端权限均生效；跨账号缓存隔离；权限丢失后不返回旧内容。
- 自动关联基于真实目录且可修改；同名歧义保留待关联；人工解除不会反复自动关联。
- 项目页任务筛选、负责人、状态、计划日期、风险、进展、原任务链接和同步时间可用。
- 无关联、无权限、未连接、无任务、当日无进展、读取失败、部分数据均有清晰状态。
- 原项目管理、日报原文、工时及财务编码功能回归通过。
- 桌面和窄屏视觉检查，真实 VivoFlow 授权与项目关联联调。

## 界面约定

面向查看研发执行情况的主管。沿用平台青绿色操作色、白色内容区、灰色结构和橙色风险提示；完成用绿色、进行中用已有蓝色语义。任务名称和异常是视觉重点，来源项目与同步时间次要。使用现有中文字体、14px 正文、16px 小标题、12px 元信息；4px 间距基准，16px 内容内边距，轻边框。以项目下的日报/研发任务双视图及按日期展开的任务进展作为主要交互，不添加无关仪表盘。

## 地址与授权回调

正式来源为 `https://flow.vivolight.cn`。2026-09-08 核实 VivoFlow 服务器代码为 `58324f62ceaef0a3fc2984c22a114029451d5ec4`，工作目录干净，业务容器正常。用户明确要求只发布日报平台：未修改 VivoFlow 业务代码、未构建或重启其服务，配套前端补丁不发布。

日报平台在独立窗口打开 VivoFlow 原有授权页面。现有 VivoFlow 使用隐藏 iframe 回调；平台的公开回调接口只校验随机 state、期限并加密暂存一次性授权码，不依赖第三方 cookie，也不在该请求中交换令牌。原平台页面通过同源 POST 轮询，由原账号、原登录会话再次校验并使用 PKCE 完成交换；不创建登录会话、不向浏览器返回令牌。拒绝授权、篡改、过期、其他会话和重放均有测试覆盖。

正式回调地址为 `{PUBLIC_BASE_URL}/api/vivoflow/callback`，不要求 VivoFlow 变更。

## 配置和运行

| 配置 | 用途 |
| --- | --- |
| `VIVOFLOW_BASE_URL` | 正式默认 `https://flow.vivolight.cn`；仅开发模式允许回环 HTTP |
| `VIVOFLOW_ENCRYPTION_KEY` | 授权凭证、待确认授权和个人缓存的加密密钥，至少 16 字符；未设置时使用 SESSION_SECRET |
| `PUBLIC_BASE_URL` | 必须是日志平台真实公开地址；用于固定回调和校验写请求 Origin |

密钥须稳定保存；更换密钥后旧授权需要重新连接。不要将密钥或本机预览数据库提交到 Git。OAuth 令牌不返回浏览器；所有任务查询同时校验本地项目权限和个人远端权限。来源内容只显示转义文字，附件在原任务查看。

平台自动建立三张独立的 `vivoflow_*` 表。首次授权后的目录读取会应用初始关联；人工解除使用持久记录，后续自动匹配不覆盖。若需把一个来源移到其他平台项目，先在原项目解除，再去目标项目选择；编辑器会显示已有归属。

```powershell
node node_modules/typescript/bin/tsc --noEmit
node --import tsx --test tests/*.test.ts
node --import tsx scripts/preview-vivoflow-manager.ts
```

模拟预览在 8137/8138 端口，仅包含演示数据。`scripts/preview-vivoflow-live.ts` 使用 8147 端口和隔离目录 `data/vivoflow-live-preview`，通过浏览器正常授权访问真实 VivoFlow；可在该目录提供仅含平台项目 id/name 和别名的 `catalog.json`。本次没有复制生产日志或凭证。预览运行时打印临时本地登录账号，两个预览不要在相同浏览器会话中同时登录（回环地址不同端口会共享 cookie）。

## 初始归属和实测

初始关联在 `src/vivoflow/initial-links.ts`，只有来源地址、来源 ID 与名称均匹配且用户有本地项目管理权限时才采用。核对了 45 个远端项目，将其中 34 个归到 6 个现有平台项目：

| 平台项目 | VivoFlow 项目数 | 范围 |
| --- | ---: | --- |
| 水锤项目 | 1 | 水锤 OCT，优先于名称包含 OCT 的通用判断 |
| 伤口荧光项目 | 1 | 伤口自发荧光成像仪 |
| OCT | 17 | 主机、导管、采集卡、软件及相应注册项目 |
| CLA | 12 | 激光模块、主机、内核、导管及相应注册项目 |
| 静脉腔闭合系统 | 2 | 系统和射频闭合导管/激光光纤 |
| 冲击波 | 1 | 栗维乐——激光冲击波 |
| AFD | 0 | 尚无明确对应项，保留待关联 |

以上初始关联已写入本机联调数据库，可编辑；生产平台尚未写入。其他来源项目没有强行关联或新建平台项目。

2026-09-08 验证结果：

- 平台 TypeScript 检查通过；180 项测试中 179 通过、1 项既有测试跳过。新增 11 项覆盖 OAuth/PKCE、错误会话与重放、令牌轮换、同源限制、权限与缓存隔离、日期边界、完整分页、部分失败、初始归属和人工修改。
- 真实账号通过 OAuth 授权并成功调用生产 MCP；完整读取 45 个项目目录。水锤 OCT 完整读取 407 个任务节点，快照 complete=true，已完成 2、进行中 10、逾期 5。所选 9 月 8 日没有填报进展；这是读取结果，不能据此认定项目没有工作。另以任务 24197 的 8 月 12 日真实进展验证正文提取，获得 97 字符非空文本。
- 浏览器验证真实目录、任务统计、逾期筛选、关联搜索、解除与恢复保存、日报/任务切换；390px 窄屏无横向溢出，弹窗操作按钮完整可见。
- 发布方案改为仅日报平台兼容原有 iframe 授权回调；配套 VivoFlow 补丁不在发布范围内。

首次读取较大的项目会逐项分页读取进展，以后台任务和同步数量提示进度；缓存按用户隔离，5 分钟后可更新。没有将来源任务数作为项目完成率，也没有把模板中未指定人员的任务推测成某人的工作。

## 后台统一读取（待指定统一账号后启用）

设置 `VIVOFLOW_SHARED_USER_ID` 为已获批准的内部平台用户 ID 后，项目任务由该用户保存的只读授权统一读取。每次查看仍先校验访问者在日报平台的项目权限；来源账号停用、授权丢失后不继续返回旧缓存。统一模式下禁止页面连接、断开和替换后台授权，普通主管无需逐人授权。

研发任务页自动发起读取，打开期间每分钟检查，五分钟缓存过期后自动更新，短暂同步错误自动重试。初始关联使用已审核的映射，人工调整不被覆盖。来源列表和任务数量不改变日报和财务数据。

管理员通过服务器 `node --import tsx scripts/configure-vivoflow-source.ts begin PLATFORM_USER_ID` 发起现有 VivoFlow 只读授权，回调仍由日报平台接收；再执行 `complete PLATFORM_USER_ID` 完成 PKCE 交换。运维随机绑定值与令牌均只加密保存在服务器，不输出密钥、不新增公开管理接口。确认后台授权后才设置统一账号并发布启用。

VivoFlow 现有授权最长 30 天，到期需管理员重新授权；本次不修改它的代码、页面、权限模型或授权期限。账号统一读取须明确批准相应任务向本平台有项目权限的主管共享。

兼容修复：个人模式的临时授权窗口改为本平台 HTTPS 页面，避免钉钉把 `about:blank` 当作外部应用协议。
