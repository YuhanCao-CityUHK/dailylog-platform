## 第 1 步：上传并解压

本地（Windows PowerShell，在 D:\日志平台 目录）：

```powershell
scp -i .\deploy\daily_report.pem .\dailylog-platform-v1.0.zip root@47.239.168.39:/tmp/
```

（如果是从压缩包外执行，请先把 zip 和 pem 的路径对应好。）

服务器上：

```bash
mkdir -p /opt/dailylog
cd /opt/dailylog
unzip -o /tmp/dailylog-platform-v1.0.zip -d app-new
# zip 内是工程根目录内容；确认结构
ls app-new/package.json app-new/src app-new/public app-new/.env >/dev/null && echo OK
# 首次部署：
mv app-new app
```

验证：`ls /opt/dailylog/app/package.json` 输出路径即可。

## 第 2 步：安装 Node.js 22（若未装）

```bash
node -v 2>/dev/null
```

若版本 ≥ v22.5 直接跳过。否则：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs
node -v   # 应为 v22.x
```

## 第 3 步：安装依赖 + 建运行账号

```bash
cd /opt/dailylog/app
npm ci --omit=dev || npm install --omit=dev
id dailylog 2>/dev/null || useradd --system --home /opt/dailylog --shell /usr/sbin/nologin dailylog
mkdir -p /opt/dailylog/app/data
chown -R dailylog:dailylog /opt/dailylog
```

## 第 4 步：核对环境配置 .env

历史生产部署曾单独提供 `/opt/dailylog/app/.env`。本仓库仅提供 `.env.example`；恢复新环境时需要单独配置全部生产凭证。以下两项也需要核对：

1. `DINGTALK_CORP_ID=`：钉钉企业 CorpId（ding 开头）。两种查法：
   - 旧系统里就有：`grep -ri "corp" /opt/dailyreport/shared/ /opt/dailyreport/current/.env* 2>/dev/null | head`（找 ding 开头的值）；
   - 或登录钉钉开放平台 open.dingtalk.com → 首页右上角企业信息。
2. `ROLE_ADMIN_USERIDS= / ROLE_EXEC_USERIDS= / ROLE_MGR_USERIDS= / ROLE_LEAD_USERIDS=`：填钉钉 userid（逗号分隔）。老板填到 EXEC，平台负责人（示例管理员）填到 ADMIN。userid 查法：
   ```bash
   cd /opt/dailylog/app && node --no-warnings -e "
   const t=async()=>{const r=await fetch('https://api.dingtalk.com/v1.0/oauth2/accessToken',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({appKey:process.env.K,appSecret:process.env.S})});const d=await r.json();
   const q=await fetch('https://oapi.dingtalk.com/topapi/v2/user/getbymobile?access_token='+d.accessToken,{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({mobile:process.argv[1]})});console.log(await q.json());};t();
   " 手机号 K=$(grep ^DINGTALK_CLIENT_ID .env | cut -d= -f2) S=$(grep ^DINGTALK_CLIENT_SECRET .env | cut -d= -f2)
   ```
   （也可以先跳过：任何人免登进来默认是 emp，之后在 .env 补上并重启即可升级角色。）

改完：`chown dailylog:dailylog /opt/dailylog/app/.env && chmod 600 /opt/dailylog/app/.env`

## 第 5 步：拷贝「日报汇总」的配置和名单（从任务工作台服务器）

日报汇总（半导体/CLA/OCT/冲击波/斑块减容/其他/静脉腔闭合系统 页签）的项目组配置与名单在**另一台服务器 47.243.199.153** 上（任务工作台）。相关配置和 SSH 密钥 `hh.pem` 由管理员单独管理，不包含在仓库中。

```bash
# 在 47.239.168.39 上执行（先把 hh.pem 传上来，或在本地中转）
chmod 600 /opt/dailylog/app/deploy/hh.pem
# 1) 找配置文件（通常在 /opt/manage_robot 的 data 卷里）
ssh -i /opt/dailylog/app/deploy/hh.pem root@47.243.199.153 "find /opt -name 'daily-report-digest.config.json' 2>/dev/null"
# 2) 按找到的路径拷贝（示例路径按上一步输出替换）
scp -i /opt/dailylog/app/deploy/hh.pem root@47.243.199.153:/opt/manage_robot/data/daily-report-digest.config.json /opt/dailylog/app/data/
# 3) 项目组名单库（含各页签的人员名单与缓存；找不到也不致命，页面里点「重新发现」可重建名单）
ssh -i /opt/dailylog/app/deploy/hh.pem root@47.243.199.153 "find /opt -name 'workbench.sqlite' 2>/dev/null"
mkdir -p /opt/dailylog/app/data/workbench
scp -i /opt/dailylog/app/deploy/hh.pem root@47.243.199.153:/opt/manage_robot/data/workbench/workbench.sqlite /opt/dailylog/app/data/workbench/
chown -R dailylog:dailylog /opt/dailylog/app/data
```

说明：配置文件里若含 `useDeployedAppCredentials: true` 的组织，会自动使用 .env 里的微光钉钉凭证；若含其它组织（如明思）的独立 appKey/appSecret，会随文件一起生效，无需改动。

## 第 6 步：初始化账号 + 起服务 + nginx + HTTPS

```bash
cd /opt/dailylog/app
sudo -u dailylog npm run init-accounts   # 记下输出的 admin / pinghu01 / pinghu02 初始密码！
cp deploy/dailylog.service /etc/systemd/system/dailylog.service
systemctl daemon-reload && systemctl enable --now dailylog
sleep 2 && curl -s http://127.0.0.1:8100/healthz    # {"status":"ok"}
curl -s http://127.0.0.1:8100/readyz                 # {"status":"ready"}

mkdir -p /var/www/letsencrypt
cp deploy/nginx-dailylog.conf /etc/nginx/sites-available/dailylog.conf
ln -sf /etc/nginx/sites-available/dailylog.conf /etc/nginx/sites-enabled/dailylog.conf
nginx -t && systemctl reload nginx
curl -s -H "Host: dailylog.vivolightsales.com" http://127.0.0.1/healthz   # {"status":"ok"}

# HTTPS（certbot 已在服务器上给旧站签过证书；给新域名单独签发，不动旧证书）
certbot --nginx -d dailylog.vivolightsales.com --no-redirect 2>&1 | tail -5 || certbot certonly --webroot -w /var/www/letsencrypt -d dailylog.vivolightsales.com
# 若用 certonly，需手动在 dailylog.conf 加 443 段后 reload（certbot --nginx 会自动加）
nginx -t && systemctl reload nginx
curl -s https://dailylog.vivolightsales.com/healthz   # {"status":"ok"}
```

## 第 7 步：钉钉开放平台配置（免登必需）

登录 open.dingtalk.com → 应用开发 → 找到 App ID `b5cdd139-d807-477e-88b9-7038e944c5c0`（ClientID example-dingtalk-client-id）这个企业内部应用：

1. 「安全域名 / 服务器出口 IP」（有的版本叫 端内免登地址/H5 可信域名）：**添加 `dailylog.vivolightsales.com`**（不要删除旧域名）。
2. 若希望内部同事从钉钉工作台直接点开新平台：应用「H5 首页地址」改为 `https://dailylog.vivolightsales.com/`。⚠️ 这一步会把点击应用的所有人带到新平台——建议先不改，等验收通过、老板拍板后再切；在那之前内部同事可先在钉钉聊天里打开链接测试免登。
3. 权限确认：应用需已开通「查询企业员工日志权限」（日报汇总用，此前已申请）、「通讯录只读」（免登取姓名）、「工作通知」（9:00 提醒用，可后开）。

## 第 8 步：验收清单

```bash
BASE=https://dailylog.vivolightsales.com
curl -s $BASE/healthz          # {"status":"ok"}
curl -s $BASE/readyz           # {"status":"ready"}
curl -s -o /dev/null -w "%{http_code}\n" $BASE/api/me        # 401（未登录，正常）
cd /opt/dailylog/app && BASE=$BASE SMOKE_EMP_LOGIN=pinghu01 SMOKE_EMP_PASSWORD=第6步的密码 SMOKE_LOGIN=admin SMOKE_PASSWORD=第6步的密码 npm run smoke
```

smoke 全绿后，人工验收：

- [ ] 浏览器打开 $BASE → 登录页；pinghu01 登录 → 强制改密 → 日志填写页可提交（AI 检查来源应显示 llm 而非 rules；若是 rules，检查服务器出网到 dashscope.aliyuncs.com）。
- [ ] 手机浏览器打开体验填写流程。
- [ ] 钉钉内（管理员/老板）打开 $BASE → 自动免登进入；管理角色能看到「日报汇总」入口，页签为 半导体/CLA/OCT/冲击波/斑块减容/其他/静脉腔闭合系统，选一个历史日期能拉到真实钉钉日报（首次拉取较慢属正常）。
- [ ] admin 登录 → 管理页可见账号列表；把 2026 年剩余法定节假日录入工作日历。
- [ ] 旧系统回归：`curl -s https://dailyreport.vivolightsales.com/healthz` 仍为 200，页面正常——确认未受影响。
- [ ] 全部通过后（可选）：.env 里 `REMINDER_ENABLED=1` 并 `systemctl restart dailylog`，开启工作日 9:00 未提交钉钉提醒。

## 回滚

新平台完全独立：`systemctl stop dailylog && rm /etc/nginx/sites-enabled/dailylog.conf && systemctl reload nginx` 即完全下线，对旧系统零影响。数据在 /opt/dailylog/app/data，删除前先备份。
